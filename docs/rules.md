# Rules catalog

Every rule Corral publishes. Groups are the unit you wire, one line each from your own root — see the
[quick start](../README.md#quick-start). A group you do not wire is not enforced; a single rule
inside one you do can be switched off with [an exclusion](excluding-a-rule.md). A few rules ship in
no group at all and are wired one at a time — they are in [Standalone rules](#standalone-rules)
below.

| Rule id | Group | What it enforces |
|---|---|---|
| `corral.test.no-mocked-repository-in-integration-test` | `TestingRulesGroup` | An `*IT` class must not declare a mocked (`@Mock`, `@MockitoBean`, `@MockBean`) field whose type ends in `Repository` or `Dao`. |
| `corral.test.no-thread-sleep` | `TestingRulesGroup` | A test class must not call `Thread.sleep`. Matched by call target owner and name, so every overload counts, and scoped to test classes — a `Sleeper` helper or a `pause()` on a base test class is flagged where it is declared, provided it compiles into test output. `TimeUnit.sleep` and other spellings of a wait are deliberately out of scope: same mistake, different predicate, so they belong under their own freeze-store key. |
| `corral.test.class-names-must-end-with-test-or-it` | `TestingRulesGroup` | A top-level class holding JUnit test methods (`@Test`, `@ParameterizedTest`, `@RepeatedTest`, `@TestFactory`, `@TestTemplate`) must end in `Test`, `Tests` or `IT`. Nested classes — including JUnit 5 `@Nested` groups — are exempt: they run through their enclosing class. |
| `corral.test.no-junit4` | `TestingJunitRulesGroup` | No class compiled into test output — test, helper, fixture or base class alike — may depend on anything `junit:junit` ships: `junit.framework..`, `junit.extensions..`, and `org.junit..` outside `org.junit.jupiter..`, `org.junit.platform..` and `org.junit.vintage..`. One bytecode dependency check, so annotations, superclasses, field and parameter types and `Assert` calls all count. Scoped to test *output* rather than to classes declaring a test: a JUnit 4 `@Before` on an abstract base class silently never runs for its Jupiter subclasses, and the base class is the only place it can be caught. Violations are per-dependency, not per-class. |
| `corral.test.junit.no-disabled-without-reason` | `TestingJunitRulesGroup` | A test class or test method annotated `@Disabled` must state a reason. The bare form, `@Disabled("")` and `@Disabled("   ")` are all flagged, one violation per offending class or method, so a fourth unexplained disable still fails a build that froze the first three. Direct annotations only: a project's own composed annotation — `@DisabledPendingFix`, itself annotated `@Disabled` — is flagged at its *declaration*, where one reason covers every use, and never at a use site, because reaching the `@Disabled` through a meta-annotation is import-scope dependent in ArchUnit and overflows the stack for a consumer who imports broadly. The conditional variants (`@DisabledOnOs`, `@DisabledIfEnvironmentVariable`, `@EnabledIf…`) are separate annotation types and are never matched. Whether the reason is *good* is not checked and is not claimed to be. |
| `corral.test.mockito.no-static-mocking` | `TestingMockitoRulesGroup` | A test class must not install a Mockito static mock. Matched through the `MockedStatic` handle as well as the `Mockito.mockStatic` call, so a base class holding a handle as a field and a helper taking one as a parameter are flagged where they declare it — whenever they compile into test output. The call check covers the remaining shape: a handle handed straight off, so no method of it is called locally. All eight `mockStatic` overloads share the name, so all eight count. Ordinary `Mockito.mock` is untouched, and a base class compiled into main rather than test output is out of scope and says so in the failure text. |
| `corral.test.mockito.no-construction-mocking` | `TestingMockitoRulesGroup` | A test class must not install a Mockito construction mock. The same two checks as the static-mock rule, over `MockedConstruction` and the `Mockito.mockConstruction` call — plus `mockConstructionWithAnswer`, which is a name of its own rather than an overload. Separate id from static mocking deliberately: the two freeze, exclude and retire independently. |
| `corral.logging.no-system-out` | `LoggingRulesGroup` | No class may access `System.out`. Matched as a field access, so every overload of `println`, plus `print`, `printf` and `write`, is covered — static initializers included. |
| `corral.logging.no-system-err` | `LoggingRulesGroup` | No class may access `System.err`. Same field-access match. Kept separate from `corral.logging.no-system-out` so stdout debt and stderr debt freeze under their own keys. `throwable.printStackTrace()` is *not* matched: the field access happens inside `java.lang.Throwable`. |
| `corral.logging.no-print-stack-trace` | `LoggingRulesGroup` | No class may call or reference `Throwable.printStackTrace`, in any overload — on any exception type, method references included. The `PrintStream` and `PrintWriter` overloads are matched even when they only render the trace into a buffer, and so is a `printStackTrace` method a project declares on its own exception type. Relies on ArchUnit resolving exception types from the classpath, its default: with it off, only a receiver declared as `Throwable` is matched. `Thread.dumpStack()` is not matched. |
| `corral.jakarta.no-javax-validation` | `JakartaMigrationRulesGroup` | No class may depend on anything in `javax.validation..` — Bean Validation moved to `jakarta.validation..` in Jakarta EE 9, and a validator ignores constraints from the other namespace rather than rejecting them, so a `javax` `@NotNull` under Hibernate Validator 8 lets `null` through with no error. One bytecode dependency check over production and test classes alike: constraint annotations, `ConstraintValidator` implementations and calls on a `ConstraintViolationException` all count, one violation per dependency. Matched by package string, so a consumer without the legacy API still runs it. A catch clause alone counts too. Not seen: constraints declared in a `validation.xml` mapping, which are not bytecode. |
| `corral.jakarta.no-javax-persistence` | `JakartaMigrationRulesGroup` | No class may depend on anything in `javax.persistence..` — JPA moved to `jakarta.persistence..` in Jakarta EE 9, and Hibernate 6 and Spring Boot 3 see only the new namespace, so a class left on `javax` compiles and is silently unmapped: an entity that is "not an entity", a column constraint never applied, an `AttributeConverter` never registered. One bytecode dependency check over production and test classes alike: mapping annotations, `AttributeConverter` implementations, `EntityManager` fields and `Query` return types all count, one violation per dependency. Matched by package string, so a consumer without the legacy API still runs it. A catch clause alone counts too. Not seen: mappings and property keys in `orm.xml` or `persistence.xml`, and `javax.transaction.Transactional`, which is JTA rather than JPA. |
| `corral.jakarta.no-javax-servlet` | `JakartaMigrationRulesGroup` | No class may depend on anything in `javax.servlet..` — the Servlet API moved to `jakarta.servlet..` in Servlet 5.0, and Tomcat 10+, Jetty 11+ and Undertow 2.3+ load only the new namespace: a `javax` filter fails registration at startup with a `NoClassDefFoundError`, or, with the old jar still on the classpath, is registered as a type the container never invokes — a security filter that silently does not run. One bytecode dependency check over production and test classes alike: `Filter` implementations, `HttpServletRequest` parameters, declared `ServletException`s, `@WebFilter` annotations and type arguments such as `List<javax.servlet.Filter>` all count, one violation per dependency. Matched by package string, so a consumer without the legacy API still runs it. Not seen: filters, servlets and listeners declared in `web.xml`, which is not bytecode. |
| `corral.spring.no-field-injection` | `SpringRulesGroup` | No field of a production class may be annotated `@Autowired`, `@Inject` or `@Resource` — `jakarta` and `javax` alike, so a codebase mid-migration is covered. A field-injected dependency is invisible to `new`, cannot be `final`, leaves the object half-built until the container fills it, and lets Spring resolve a dependency cycle that constructor injection would fail at boot. One violation per field, so a fourth injected field in a class frozen with three still fails. `@Value` fields, static fields without an injection annotation, constructors and `@Bean` method parameters are untouched, and test classes — by output location or a declared test method, never by name — are out of scope, so `@Autowired` on a `@SpringBootTest` field is fine. Not seen: a dependency pulled from an injected `ApplicationContext` with `getBean`, a project's own annotation meta-annotated with `@Autowired`, and XML bean definitions. |
| `corral.spring.no-setter-injection` | `SpringRulesGroup` | No method of a production class may be annotated `@Autowired`, `@Inject` or `@Resource` — `jakarta` and `javax` alike, so a codebase mid-migration is covered. A dependency injected through a method cannot be `final`, leaves the object half-built until the container calls it, and turns the collaborator into public API anything can rebind. Matched on the annotation, not the name, so an `@Autowired` multi-argument `wire(…)` method counts; one violation per method. Constructors, `@Bean` factory methods and plain unannotated setters are untouched, and test classes — by output location or a declared test method, never by name — are out of scope. An `@Autowired` configuration method in a `@Configuration` class is a legitimate framework pattern and is meant to be frozen as debt. Not seen: field injection, a project's own annotation meta-annotated with `@Autowired`, and XML bean definitions. |
| `corral.spring.no-transactional-on-private-method` | `SpringRulesGroup` | No `private` method may be annotated `@Transactional` — Spring's, `jakarta`'s or `javax`'s, directly or through a project's own composed annotation such as `@ReadOnlyTransaction`. Spring's transactions live in a proxy that can neither override nor intercept a private method, so the annotation does nothing and every call inside auto-commits on its own; nothing warns at startup. `private final` methods and private methods on a `final` class count; one violation per method. Public, protected and package-private transactional methods are untouched — Spring 6 class-based proxies advise the latter two, so on Spring 5, where they are inert too, this rule deliberately does not see them. A class-level `@Transactional` never applies to private methods, so an unannotated private method in an annotated class is fine. Production and test classes alike. Matched by annotation name, so a consumer without `spring-tx` still runs it. Not seen: a non-private method called from inside its own class, which bypasses the proxy just the same. A project on AspectJ weaving (`AdviceMode.ASPECTJ`) gets transactions on private methods and should not adopt the rule. |
| `corral.spring.no-transactional-on-final-or-static` | `SpringRulesGroup` | No `@Transactional` method — Spring's, `jakarta`'s or `javax`'s, directly or through a project's own composed annotation — may be `final`, `static`, or declared in a `final` class. Spring Boot's CGLIB proxy advises a method by overriding it in a runtime subclass: a `final` class fails at startup only once that bean is wired, while a `final` or `static` method is silently called on the target with no transaction, so every write inside auto-commits on its own. A class-level `@Transactional`, on the class or any superclass, makes every non-static method transactional, so a `final` one there counts too; a static method counts only when annotated itself. One violation per method. Private methods are never reported here, and compiler-generated bridge methods are skipped so a generic override is reported once. Production and test classes alike. Matched by annotation name, so a consumer without `spring-tx` still runs it. Not seen: a `@Transactional` declared only on an implemented interface. A project on AspectJ weaving (`AdviceMode.ASPECTJ`) advises final and static methods and should not adopt the rule. |
| `corral.spring.no-async-on-unproxyable-method` | `SpringRulesGroup` | No `@Async` method — directly or through a project's own composed annotation — may be `private`, `static`, `final`, or declared in a `final` class. Spring Boot's CGLIB proxy advises a method by overriding it in a runtime subclass: a `final` class fails at startup only once that bean is wired, while a `private`, `static` or `final` method is silently called on the target and runs synchronously on the caller's thread — the work still happens, it just blocks the thread it was meant to free. Protected and package-private `@Async` methods are intercepted and are untouched. A class-level `@Async`, on the class or any superclass, makes every non-private, non-static method async, so a `final` one there counts too; a private or static method counts only when annotated itself. One violation per method; compiler-generated bridge methods are skipped. Production and test classes alike. Matched by annotation name, so a consumer without `spring-context` still runs it. Not seen: an `@Async` declared only on an implemented interface, and an `@Async` method called from inside its own class, which bypasses the proxy just the same. A project on AspectJ weaving (`AdviceMode.ASPECTJ`) advises these methods and should not adopt the rule. |
| `corral.spring.no-final-component` | `SpringRulesGroup` | No production class carrying a Spring stereotype — `@Component` directly, or through `@Service`, `@Repository`, `@Controller`, `@Configuration` or a project's own composed annotation — may be `final`; a `@Component` record counts, being implicitly final. Spring Boot's CGLIB proxy is a runtime subclass, so the moment anything advises the bean — `@Transactional`, `@Async`, `@Cacheable`, method security, a scoped proxy or a matching `@Aspect` — creating it fails with "Cannot subclass final class", often only in production, where the real bean is first built and advised. Reported whether or not anything advises the class today, `@Configuration(proxyBeanMethods = false)` included; one violation per class. Test classes — by output location or a declared test method, never by name — are out of scope. Matched by annotation name, so a consumer without `spring-context` still runs it. Not seen: a `sealed` bean class, and a final class registered through a `@Bean` method. A project on AspectJ weaving (`AdviceMode.ASPECTJ`), or one that deliberately uses interface-based JDK proxies everywhere, should not adopt the rule. |
| `corral.spring.no-component-on-abstract-class` | `SpringRulesGroup` | No abstract production class may carry a Spring stereotype — `@Component` directly, or through `@Service`, `@Repository`, `@Controller` or a project's own composed annotation. Component scanning accepts only concrete classes, so the annotation creates no bean and no warning; and since `@Component` is not `@Inherited`, a subclass written without its own stereotype is silently not a bean either. One violation per class. Not matched: an abstract class declaring a `@Lookup` method (inherited ones do not count, as for Spring), an abstract `@Configuration` (processed when reached through `@Import`), interfaces such as Spring Data repositories, and annotation types. Test classes — by output location or a declared test method, never by name — are out of scope. Matched by annotation name, so a consumer without `spring-context` still runs it. Not seen: an empty `@Lookup` method added only to hit Spring's carve-out, and an abstract class whose stereotype was swapped for `@Configuration`. |
| `corral.spring.no-application-context-injection` | `SpringRulesGroup` | No production class may depend on a type assignable to `org.springframework.beans.factory.BeanFactory` — `ApplicationContext`, `ConfigurableApplicationContext`, `ListableBeanFactory`, `AutowireCapableBeanFactory` and every other subtype. A class that holds the container and calls `getBean` is a service locator: its real dependencies vanish from the constructor, and a missing or ambiguous bean no longer stops the context from starting but throws on the first code path that asks for it. One bytecode dependency check, so constructor parameters, fields, return types and calls all count, and so do `ApplicationContextAware` and `BeanFactoryAware`, whose callbacks take the container as a parameter; one violation per dependency. `ApplicationEventPublisher`, `ObjectProvider`, an injected `Map` or `List` of beans and a Boot `main` that only calls `SpringApplication.run(...)` are untouched. A `BeanFactoryPostProcessor` class and an `ApplicationContextInitializer`, whose signatures hand over the container, are reported, and so is a custom `Condition` or a Quartz `JobFactory` that calls the bean factory; these are meant to be frozen as debt. Test classes — by output location or a declared test method, never by name — are out of scope, so a test autowiring the context is fine. Matched by name, so a consumer without Spring still runs it. Not seen: callers of a static context holder, and a subclass calling a lookup helper its container-aware base class defines — only the holder and the base class are reported, and a holder shipped by a library is not reported at all; and a lambda `BeanFactoryPostProcessor` that calls no method on the factory. Needs ArchUnit's default `resolveMissingDependenciesFromClassPath=true`: with it off, `ApplicationContext` and its subtypes are stubs and only a literal `BeanFactory` dependency is reported. |
| `corral.security.no-jdbc-statement` | `SecurityRulesGroup` | No production class may call `Connection.createStatement`. A plain `Statement` takes its SQL as a string the caller has already assembled, so user input concatenated into it is query text, not a value — the SQL injection vector; a `PreparedStatement` with bound `?` parameters removes it. Matched by call target owner and name, so all three overloads count, as does a call through a driver's own `Connection` subinterface; one violation per call. `prepareStatement`, `prepareCall` and every `Statement` method are untouched, and test classes — by output location or a declared test method, never by name — are out of scope, so a test building its fixture schema is fine. The call is seen, the SQL string never is: a `PreparedStatement` built from a concatenated string, and `JdbcTemplate` or JPA handed one, are just as injectable and not caught. DDL and other constant, input-free statements are legitimate exceptions; freeze them — an exclusion switches the rule off for the whole build. |
| `corral.java.no-bigdecimal-double-constructor` | `JavaCorrectnessRulesGroup` | No class may call or reference a `BigDecimal` constructor whose first parameter is a `double` — `new BigDecimal(double)`, `new BigDecimal(double, MathContext)` or `BigDecimal::new` on a `double`. The constructor is exact, so `new BigDecimal(0.1)` carries all 55 digits of the binary value the `double` holds: it is not `equals` to `new BigDecimal("0.1")`, `compareTo` ranks it above `0.1`, and its scale of 55 grows with every `multiply`. `BigDecimal.valueOf(double)` goes through `Double.toString` and gives `0.1`; a literal belongs in the `String` constructor, and a `float` in `new BigDecimal(Float.toString(f))`. A `float` argument is flagged too, since the compiler widens it to the `double` constructor. One violation per call or reference, a call inside a lambda included; production and test classes alike. `valueOf`, the `String`, `int` and `long` constructors, and `BigDecimal::valueOf` are untouched. Not seen: a `BigDecimal` built from a `double` by reflection or inside a library. Code that exists to show a `double`'s exact binary value is the legitimate exception; freeze it — an exclusion switches the rule off for the whole build. |
| `corral.java.public-static-fields-must-be-final` | `JavaCorrectnessRulesGroup` | A `public static` field of a production class must be `final`. A non-final one is global state with no owner: every class that can see it can reassign it, its value depends on class-initialisation order, and an unsynchronised write gives other threads no happens-before edge. `final` fixes a field that is never reassigned — with `List.copyOf`, `Set.of` or `Map.of` if it holds a collection — and an injected collaborator replaces one that is. One violation per field. Private, protected and package-private statics and instance fields are untouched; the declaring class's own visibility is not read, so a `public static` field of a package-private or private nested class is flagged. Test classes — by output location or a declared test method, never by name — are out of scope; a shared test-support module's main sources and Gradle `testFixtures` or `integrationTest` output are production output, so a test helper there is flagged unless it declares a test method itself. Fields of a class annotated `@StaticMetamodel`, `jakarta` or `javax`, are exempt: the JPA specification requires their attributes to be `public static volatile`. Only the field's modifiers are read, so a `final` field holding a mutable object — an `AtomicReference`, a mutable collection — is not seen, and neither is a mutable field narrowed to `private`, `protected` or package-private, setter or not. Compiler-generated fields are not exempt: every Groovy class, enum, closure and trait helper — not interfaces, traits or a Groovy 4 `@POJO` class — is flagged on the `public static transient boolean __$stMC` Groovy adds. A Kotlin `lateinit var` or `@JvmField var` in a companion object or `object` compiles to a `public static` non-`final` field and is flagged. Generated code you cannot edit — an ANTLR lexer's `modeNames` and `channelNames` — freezes as debt; a Groovy codebase, or an Android module whose generated `R` classes hold non-final ids since AGP 8, adds a violation with every new class and excludes the rule, which switches it off for the whole build. |
| `corral.java.no-public-static-array-fields` | `JavaCorrectnessRulesGroup` | No `public static` field of a production class may be declared with an array type, `final` or not. An array is mutable whatever its modifiers — `final` fixes the reference, not the contents — so `Defaults.NAMES[0] = null` compiles from any class that can see the field, and a caller that sorts the "constant" changes it for everyone. `List.of(...)` replaces an array constant; where callers need an array, a private field returned through `clone()` from a method. Interface fields count, being implicitly `public static final`, so an array moved into an interface is still flagged. A zero-length array constant is flagged too, though nothing can be written into it, because only the declared type is read: make it private behind a method, or freeze it. One violation per field. Private, protected and package-private arrays, instance arrays and enums — whose compiler-generated `$VALUES` is private — are untouched; the declaring class's own visibility is not read. Test classes — by output location or a declared test method, never by name — are out of scope; a shared test-support module's main sources and Gradle `testFixtures` or `integrationTest` output are production output, so a test helper there is flagged unless it declares a test method itself. Not seen: `new ArrayList<>(...)` or `Arrays.asList(...)` in place of the array, a narrowed field whose getter returns the array itself, and a holder object exposing it. Generated code you cannot edit — ANTLR lexers' and parsers' `ruleNames` and `tokenNames`, a lexer's `modeNames` and `channelNames` — freezes as debt. |
| `corral.java.no-class-new-instance` | `JavaCorrectnessRulesGroup` | No class may call or reference `Class.newInstance()`, deprecated since Java 9 — the direct call, `Class.forName(name).newInstance()`, `Class::newInstance` and a call inside a lambda alike. It rethrows whatever the constructor throws, checked exceptions included, though its `throws` clause names only `InstantiationException` and `IllegalAccessException`, so a constructor's `IOException` escapes a caller the compiler believes cannot see one. `clazz.getDeclaredConstructor().newInstance()` finds the same no-arg constructor under the same access check and wraps every constructor exception in `InvocationTargetException`; unwrap it so callers catching a specific runtime exception still see it. One violation per call or reference; production and test classes alike. `Constructor.newInstance`, `Array.newInstance` and a project's own `newInstance` methods are untouched. Not seen: `Class.newInstance` invoked by reflection or inside a library, and how the replacement's exceptions are caught. |
| `corral.java.no-finalize-override` | `JavaCorrectnessRulesGroup` | No class or interface may declare a no-arg `finalize()` — `Object.finalize()` is deprecated since Java 9 and for removal since Java 18 (JEP 421), and `--finalization=disabled` already turns it off with no error. A finalizer may never run, so a resource it releases leaks; when it does run it runs late, on one JVM-wide thread, keeps the instance alive an extra GC cycle, swallows its own exceptions and can resurrect `this`. `AutoCloseable` with try-with-resources replaces it, with `java.lang.ref.Cleaner` as a backstop whose action must not capture the object; on Java 22+, `java.lang.foreign.Arena` scopes native memory. Matched on declared methods by name and empty parameter list, so any visibility counts, as does an interface declaring `void finalize()`, while a class that only inherits `Object.finalize` and a domain `finalize(Order)` are untouched; one violation per method, production and test classes alike. The body is not read, so the empty `protected final void finalize() {}` written to stop a subclass installing a finalizer is flagged too — the legitimate exception, frozen as debt along with finalizers in generated code. Not seen: `System.runFinalization()` and `Runtime.runFinalization()` calls, a `dispose()` nothing calls, a `Cleaner` action that captures the object, and a hand-rolled `PhantomReference` queue. |
| `corral.concurrency.no-object-monitor-methods` | `ConcurrencyRulesGroup` | No class may call `Object.wait`, `notify` or `notifyAll` — coordination between threads goes through `java.util.concurrent`. `wait` wakes spuriously, so a waiter without a re-checking loop acts on state that is not there; a `notify` nobody is waiting for is lost, so the waiter arriving later hangs with no exception and no log line. Matched by name and exact parameter list — the five signatures are `final` on `Object` — so a call on `this`, on an `Object` lock or on a receiver typed as a collection or an interface counts, and a domain `notify(long)` does not. A method reference such as `lock::notifyAll` counts as well, as does `TimeUnit.timedWait`, which calls `Object.wait` itself; one violation per call or reference. Test classes are in scope. `Condition.await`/`signal`, `LockSupport.park` and `Thread.sleep` polling loops are not caught; translating `wait` to `Condition.await` and `notify` to `signal` one for one keeps both bugs. A class implementing a concurrency primitive, or bridging a callback-based native or vendor API, is the legitimate exception: freeze it as debt. |
| `corral.concurrency.no-manual-thread-creation` | `ConcurrencyRulesGroup` | No production class may call or reference a constructor of `java.lang.Thread`, `java.util.Timer` or a subclass of either — work goes to an `ExecutorService` the application owns. A raw thread is uncapped, unqueued, unstopped and, unless every call site names it, unnamed: a thread per request ends in `OutOfMemoryError: unable to create native thread`, the dump is a wall of `Thread-247`, and a non-daemon thread no shutdown path knows about keeps the JVM alive. Each `Timer` starts its own thread, non-daemon by default, and one task that throws kills it along with every task still scheduled. Matched by constructor owner assignability, so every overload counts, as does a `Thread::new` reference, a hand-written `ThreadFactory`, an anonymous `new Thread() { … }` and a JDK or library subclass such as `ForkJoinWorkerThread`; one violation per call or reference. A project's own subclass is reported where its constructor calls its parent's and again at every `new` of it, so an anonymous thread is two lines. `javax.swing.Timer`, `TimerTask`, `Thread.currentThread()` and a submitted task are untouched, and test classes — by output location or a declared test method, never by name — are out of scope. A shared test-support module's main sources and Gradle `testFixtures` or `integrationTest` output are production output, so a thread-spawning test helper there is flagged unless it declares a test method itself. Not seen: `Thread.ofPlatform().start(...)`, `Thread.startVirtualThread(...)`, `Executors.defaultThreadFactory().newThread(...)`, a fresh `newSingleThreadExecutor()` per call, `CompletableFuture.runAsync` without an executor, `Executors.newCachedThreadPool()`, whose thread count is uncapped, and a `Thread` built by reflection. A shutdown hook — `Runtime.addShutdownHook` takes only a `Thread` — and pool infrastructure that must build its own threads are the legitimate exceptions: freeze them as debt. Needs ArchUnit's default `resolveMissingDependenciesFromClassPath=true`: with it off, JDK and library subclasses are stubs, so their constructor calls are missed, and so is every construction of a project class extending one. |
| `corral.exception.no-generic-exception-thrown` | `ExceptionRulesGroup` | No production class may call or reference a constructor of exactly `java.lang.Throwable`, `Error`, `Exception` or `RuntimeException` — throw a type that names the failure. An untyped exception can only be told apart by its message: a `catch (RuntimeException e)` also catches every `NullPointerException`, and retry policies, `@ControllerAdvice` handlers and circuit breakers that dispatch on type send a retryable timeout and a permanent "not found" down the same path. Matched by constructor owner, so every overload counts, as does a `RuntimeException::new` reference and a static factory on a subclass returning `new RuntimeException(...)`; one violation per call or reference; an instance field initialiser is reported once per constructor that runs it, under that constructor's signature, so adding or changing a constructor in its class reports it again. An anonymous `new RuntimeException("x") {}` is reported on the anonymous class's constructor (`OrderService$1.<init>`), not on the throwing method. A named direct subclass's constructor calling its superclass's constructor is exempt, and ArchUnit cannot tell `super(...)` from any other such call there, so an instance of the superclass's own type built in that constructor — `super(msg, new RuntimeException("inner"))` in a `RuntimeException` subclass, a field initialiser or a lambda — is not seen; one of the other three types, or a constructor reference, still is. Subclasses, `IllegalStateException`, `IllegalArgumentException`, `AssertionError` and a rethrown caught throwable are untouched, and test classes — by output location or a declared test method, never by name — are out of scope. A shared test-support module's main sources and Gradle `testFixtures` or `integrationTest` output are production output, so a stub there throwing `new RuntimeException("boom")` is flagged unless it declares a test method itself. Not seen: a helper's callers (only the helper is reported), a library helper that constructs one internally, such as Guava's `Throwables.propagate`, `@SneakyThrows`, and a catch-all type of the project's own. ## Standalone rules

These ship in the artifact but belong to no group, because a group is adopted whole: everything in
one runs for everybody who wires it, and these are rules a team can reasonably decline. Wire one by
naming the rule class, which is exactly what a group's own field does — same freezing, same
exclusions, same failure output.

import io.github.milczekt1.corral.rules.testing.nomutablestaticstate.NoMutableStaticStateRule;

## Rule ids

**Rule ids are freeze-store keys.** Changing an id orphans every consumer's frozen entry, so treat it
as a breaking change.

Every id Corral publishes starts with the `corral.` vendor prefix, so it can never collide with a
namespace you pick for your own rules — `acme.no-stdout-in-services` in the
[example consumer](../corral-example) shows the generic namespace this frees up. After the prefix, an
id is a dot-namespaced, kebab-cased shape, and every slug carries exactly one of two markers: `no-`
for a prohibition (`corral.logging.no-system-out`) or `-must-` for an obligation
(`corral.test.class-names-must-end-with-test-or-it`). Ids are never renamed, only deprecated — the
old one stays registered, always passing, naming its replacement. The full grammar and the reason
renaming is unsafe are in [CONTRIBUTING.md § Rule ids](../CONTRIBUTING.md#rule-ids).
